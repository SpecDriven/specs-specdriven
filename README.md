# Specdriven Application

## Mission

- Local first application whose only required dependency is git version control
- Loved by solo developers and small teams for its simplicity

## Requirements

- Support for GitHub and GitLab

## Working agreemnents

- All features need specifications
- The majority of scenarios need links to automated tests

## Proposing specs

We don't accept pull requests to the app (roadmap/moving-to-proper-open-source.md);
we welcome proposed specs instead. A proposal is a feature, or a scenario
added to one, written like the files under `specs/`: a `# feature` heading,
a short description, and `## scenario @v1 [proposed]` sections with
`- Given:` / `- When:` / `- Then:` steps. We publish the ones we build.

Soon you will sign in with GitHub and propose straight into this repo (with
a daily limit per account). Until then, open an issue on
SpecDriven/specdriven-app-release with your proposal.
