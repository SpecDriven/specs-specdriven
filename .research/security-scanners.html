Free Security Scanners for the SpecDriven Pipeline

Research notes — 2026-08-31 · Context: Bun + TypeScript + Electron app, Dockerfile, single GitHub Actions workflow (test.yml). Goals: prevent supply-chain attacks and catch insecure code written by AI agents.

1. Supply chain — malicious or vulnerable dependencies

bun audit implemented ✓

Bun's built-in vulnerability audit (equivalent of npm audit). Added as a separate audit job in test.yml so a vulnerable dependency fails as its own check without masking test results. Exits non-zero on vulnerabilities of any severity; relax later with bun audit --audit-level=high if it gets noisy.

Outcome: the first local run found 16 vulnerabilities (9 high) in transitive dev dependencies under electron/electron-builder — undici, fast-uri, brace-expansion, js-yaml. All fixes were already within the parents' semver ranges, so regenerating bun.lock from the unchanged package.json cleared all of them. All 575 tests pass on the refreshed lockfile.

Bun minimumReleaseAge recommended next

In bunfig.toml, set a cooldown (e.g. 3–7 days) so freshly published package versions can't be installed. One of the most effective defenses against npm account-takeover attacks, where malicious versions are usually yanked within hours or days of publication.

[install]
# don't install versions published less than 3 days ago
minimumReleaseAge = 259200

2. CI hardening — the pipeline is itself a supply-chain target

  • zizmor — audits GitHub Actions workflows for injection vulnerabilities, unpinned actions, excessive permissions, and cache poisoning. Fast, excellent signal, free.
  • Pin actions by commit SHA instead of tags (actions/checkout@<sha>) and set permissions: contents: read as the workflow default. Dependabot keeps the SHAs updated.
  • StepSecurity harden-runner — egress monitoring/blocking for Actions runners; free for public repos. Would have caught several real-world exfiltration attacks.

4. Agent-specific guardrails

  • Run Claude Code's built-in /security-review on branches before merging.
  • Make the scanners required PR checks — CI enforcement is the backstop that doesn't depend on the agent behaving.
  • Pre-commit hook with Gitleaks + semgrep --config auto catches problems before they reach a commit an agent might push.

5. Rollout order (value ÷ effort)

  1. Dependabot + bun audit in CI — done
  2. minimumReleaseAge in bunfig.toml
  3. Semgrep + Gitleaks jobs in CI
  4. zizmor + SHA-pin all actions
  5. Electronegativity and Trivy (Electron app + Docker image)
